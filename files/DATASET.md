# Test data: sources, licences and limits

These files are used to **evaluate Blackout's rule-based detection**. Nothing here trains a model, and no dataset is bundled with the app.

## 1. Public synthetic dataset (not bundled; you download it)

| | |
|---|---|
| Name | `gretelai/synthetic_pii_finance_multilingual` |
| Where | https://huggingface.co/datasets/gretelai/synthetic_pii_finance_multilingual |
| Licence | Apache-2.0 (stated on the dataset card) |
| Content | Synthetic financial documents with character-offset PII span labels. 29 PII types, 100 document formats, 55,940 records (English, Spanish, Swedish, German, Italian, Dutch, French), generated with Gretel Navigator |
| Citation | Watson, Meyer, Van Segbroeck, Grossman, Torbey, Mlocek, Greco (2024). *Synthetic-PII-Financial-Documents-North-America: A synthetic dataset for training language models to label and detect PII in domain specific formats.* Gretel.ai, June 2024. |

**Why the labels are not trusted blindly.** The dataset card says the spans were labelled by an NER model, filtered by an LLM judge, and only spot-checked by people, and that errors may remain. `convert-gretel.py` therefore checks every span before it is used for scoring:

- the span must lie inside the text and not be empty;
- an email span must contain `@`; a phone span must have 7 to 15 digits; a date of birth must contain digits; a credential or address must not be trivially short;
- a `name` span that looks like an organisation (Ltd, Inc, Bank, ...) is set aside, because the `name` type mixes people and companies;
- a card number must pass the Luhn check, otherwise its label cannot be verified;
- nested duplicates (a `first_name` inside a `name`) are dropped.

A span that fails a check goes to a rejected-span audit file (offsets and reasons only) **and** is marked "ignore": a detection on it is counted separately instead of as a false positive, and it is not counted as a miss. Types Blackout does not target (`company`, `date`, `time`, `date_time`) are ignored the same way. The type mapping is in `data/label-mapping.json`.

**What this dataset cannot tell you.** It has no Indian identifiers, and it is mostly structured finance documents (XML, JSON, forms, emails). Scores on it say little about letters, scanned documents or Indian addresses.

**How to use it**

1. Download a slice of the English test split from the dataset page (Files tab, `data/`).
2. `python3 tests/convert-gretel.py <downloaded file> --limit 500 --out tests/data/gretel-english.jsonl`
3. `node tests/run-tests.js tests/data/gretel-english.jsonl`, or open the page, expand "Detection test (advanced)" and pick the converted file.

The converter has been exercised only on a few rows I wrote in the dataset's column format. **It has not been run on the real dataset, and no real dataset rows were used for any result reported with this project.**

## 2. Hand-authored synthetic files (bundled)

Generated by `tools/make-synthetic.js` with a fixed seed, so they can be regenerated exactly. Every name, address, number and key is invented (`example.com` addresses, made-up people, random digits).

| File | Documents | Purpose |
|---|---|---|
| `data/synthetic-sample.jsonl` | 129 | Names, emails, phones, addresses, dates of birth, passwords and keys, card and bank details, ID numbers, structured text (JSON and XML), names with initials, and documents with nothing sensitive |
| `data/indian-ids.jsonl` | 56 | Aadhaar and PAN cases, positive and negative (see below) |

**Labels are correct by construction.** Aadhaar numbers are generated with a valid Verhoeff check digit (or deliberately an invalid one), card numbers pass Luhn, and PANs use a valid (or deliberately invalid) holder-type letter. `run-tests.js` re-verifies this on every run and fails if a bundled label contradicts its tag.

**Tags.** `hard` marks cases the rules are known to miss or get wrong (names that are in neither the built-in list nor a label, lowercase addresses, unlabelled account numbers, a plain 10-digit order number). Report them, but keep them out of regression floors (`--skip-hard`). `negative` marks documents with nothing sensitive.

**The identifier rules, and where they come from**

- Aadhaar: 12 digits, first digit 2 to 9, not a palindrome, last digit a Verhoeff check digit (as implemented in the open-source python-stdnum library). An unlabelled number must pass; a number after a label such as "Aadhaar:" is accepted even if the check fails, and the reviewer is told the check digit does not match.
- PAN: ten characters, fourth letter the holder type, one of P, C, H, F, A, T, B, L, J, G (Income Tax Department guidance as reproduced on public pages). An unlabelled PAN needs a valid holder type; a labelled one is accepted either way.

**Limit of these files.** The same person wrote the rules and these examples, so scores on them are optimistic. Treat them as a regression guard, not as an accuracy claim. Use the public dataset for an independent view.

## 3. Test file format

One JSON object per line (or a JSON array):

```json
{"id": "doc-1", "text": "Name: Priya ...", "spans": [{"start": 6, "end": 17, "label": "Name"}],
 "ignore": [{"start": 40, "end": 52}], "tags": ["hard"]}
```

Labels Blackout scores: Name, Email, Phone, Address, ID number, Financial, Credential, Date of birth, Other.
